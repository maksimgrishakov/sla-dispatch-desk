# 🛡️ SLA Dispatch & Routing Desk
**Автоматизированная система диспетчеризации клиентских обращений, контроля SLA и балансировки нагрузки инженеров технической поддержки**

Учебный проект по бизнес-анализу, системному анализу и разработке бизнес-приложений на языке Python.

## 1. Описание бизнес-проблемы (AS-IS)
В сервисных B2B-компаниях, обслуживающих розничные торговые точки и кассовую ИТ-инфраструктуру по договорам абонентского обслуживания (SLA), первичная обработка входящих заявок часто выполняется вручную:
* **Потеря критических инцидентов:** координатор вручную разбирает поток писем и сообщений, из-за чего аварии с полной остановкой касс у VIP-клиентов теряются среди несрочных консультационных запросов.
* **Отсутствие проактивного контроля сроков (SLA):** дедлайны по договорам клиентов не рассчитываются автоматически при приеме заявки, а штрафы за просрочку выявляются только в конце месяца.
* **Неравномерная загрузка инженеров:** заявки распределяются без учета текущей сложности задач, уже находящихся в работе у каждого специалиста.

## 2. Предлагаемое решение (TO-BE)
Разработано локальное веб-приложение на базе **Python + Streamlit + SQLite**, которое автоматизирует полный цикл диспетчеризации:
1. **Автоматический триаж текста обращения (NLP Rule-Engine):** мгновенное определение категории (`Кассовое ПО`, `Оборудование / POS`, `Сеть и Фискализация (ОФД)`, `Консультация и Отчетность`) и уровня приоритета (`Critical`, `High`, `Medium`, `Low`) по словарям маркеров критичности.
2. **Расчет дедлайна по матрице SLA:** автоматическое вычисление крайнего срока решения (`SLA Deadline`) на основе пересечения тарифа клиента (`VIP`, `Standard`, `Basic`) и приоритета заявки.
3. **Умная автомаршрутизация (Smart Routing):** назначение заявки профильному инженеру на смене с минимальным текущим **взвешенным индексом загрузки (Workload Score)** (`Critical = 4 балла`, `High = 3`, `Medium = 2`, `Low = 1`).
4. **Монитор «Светофор SLA» в реальном времени:** динамическая подсветка заявок (`🟢 В норме`, `🟡 Риск просрочки (<25% времени)`, `🔴 Просрочено`) и аналитический дашборд руководителя с расчетом KPI (`SLA Compliance Rate`, `MTTR`, оценка штрафных рисков).

> **Примечание о данных:** Все компании-клиенты, ФИО сотрудников и обращения в базе данных являются **синтетическими** и генерируются автоматически для демонстрации бизнес-логики.

## 3. Стек технологий
* **Язык программирования:** Python 3.10+
* **Веб-интерфейс:** `Streamlit`
* **СУБД:** `SQLite3` (встроенная реляционная база данных)
* **Аналитика и визуализация:** `Pandas`, `Plotly Express`
* **Тестирование:** `Pytest`

## 4. Структура проекта
```text
sla-dispatch-desk/
├── app.py              # Главный модуль пользовательского интерфейса (Streamlit)
├── database.py         # Слой работы с БД SQLite и генератор синтетических демо-данных
├── services.py         # Ядро бизнес-логики (классификация, матрица SLA, автомаршрутизация)

├── requirements.txt    # Зависимости проекта
├── .gitignore          # Правила исключения временных файлов для Git
└── README.md           # Документация проекта
```

## 5. Инструкция по установке и локальному запуску

### Шаг 1. Клонирование репозитория и переход в папку проекта
```bash
git clone <URL_вашего_репозитория>
cd sla-dispatch-desk
```

### Шаг 2. Создание виртуального окружения (рекомендуется) и установка библиотек
Для **Windows**:
```bash
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

Для **macOS / Linux**:
```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### Шаг 3. Запуск приложения
```bash
streamlit run app.py
```
После выполнения команды приложение автоматически откроется в браузере по адресу `http://localhost:8501`. При первом запуске автоматически создается файл базы данных `sla_dispatch.db` и заполняется актуальными демонстрационными данными.

### Шаг 4. Запуск автоматических тестов
```bash
pytest test_services.py -v
```
